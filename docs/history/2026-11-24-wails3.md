# Wails v2 → v3.1.0 升级分析与计划
## 一、结论摘要
根据 [Wails 官方迁移指南](https://wails.io/migration/v2-to-v3)（v3 是**完全重写**，v2/v3 通过不同 import path 可并存），以及 [v3.1.0 发布说明](https://wails.io/blog/wails-v3-1-released)（2026-11-01 发布，含 100+ 修复、实验性 CGO-free 构建与 Wake 构建系统），本项目的迁移面**相当小**：
> ✅ 核心优势：前端所有后端调用都收敛在 `api/bindings.ts` 的 `call()` 封装、所有事件订阅都收敛在 `api/events.ts` 的 `on()` 封装。**改 2 个适配层文件即可覆盖 40+ 绑定方法和 6 类事件**，视图层几乎零改动。
预计工作量：**0.5~1.5 天**（官方估计典型应用 1-4 小时，本项目额外需要回归任务队列/对话框/日志链路）。
---
## 二、现状依赖盘点（逐文件）
| 文件 | v2 用法 | v3.1.0 对应 |
|---|---|---|
| `go.mod` | `github.com/wailsapp/wails/v2` | `github.com/wailsapp/wails/v3 v3.1.0` |
| `main.go` | `wails.Run(&options.App{Bind: ...})` 单体式启动 | `application.New()` → `app.Window.NewWithOptions()` → `app.Run()` 三阶段 |
| `app.go` | `startup(ctx)`/`shutdown(ctx)` 生命周期方法；`runtime.EventsEmit(ctx,...)`；`runtime.OpenDirectoryDialog/OpenFileDialog/SaveFileDialog(ctx,...)` | `ServiceStartup(ctx, opts)`/`ServiceShutdown()`；`app.Event.Emit()`；`app.Dialog.OpenFile().CanChooseDirectories(true)...PromptForSingleSelection()` |
| `bindingtag_bindings.go` / `bindingtag_default.go` | `-tags bindings` 构建标签：v2 生成绑定时**编译并执行本程序**（不启动窗口），用于跳过 `config.yml` 落盘 | **可整体删除**：v3 绑定生成是纯静态分析（`wails3 generate bindings`），不运行程序，此规避机制失去存在必要 |
| 前端 `api/bindings.ts` | `window.go.main.App.<Method>` 桥接 | `@wailsio/runtime` 的 `Call.ByName("main.App.<Method>", ...)`（或生成的绑定模块） |
| 前端 `api/events.ts` | `window.runtime.EventsOn/Off/Emit`，回调 `(...data)` 取 `data[0]` | `@wailsio/runtime` 的 `Events.On`（回调签名变为 `(event)` 取 `event.data`）、`Events.Emit` 返回 `Promise<boolean>` |
| 前端 `env.d.ts` | 自定义 `WailsRuntime`/`window.go`/`window.runtime` 声明 | 删除（运行时由 npm 包提供类型） |
| `frontend/package.json` | 无 runtime 依赖（v2 是全局注入） | 新增 `"@wailsio/runtime": "^3.x"` |
| `wails.json` | v2 字段（`frontend:install` 等） | v3 结构（`frontend.dir/install/build/dev/devServerUrl`），构建编排转由 **Taskfile.yml** 承担 |
| `build.ps1` | `wails build`；回退 `go build -ldflags="-H windowsgui"` | `wails3 build`（内部走 Task）；回退需加 `-tags production,desktop` |
| `.gitignore` | `frontend/wailsjs/` | 改为 `frontend/bindings/` |
| `AGENTS.md` / `README.md` | v2 术语与命令 | 同步 v3 事实 |
**未使用**（无需迁移）：多窗口、系统托盘、菜单、Systray、SingleInstance、Wails logger（项目自有 `logx`）——这是迁移面小的主要原因。

## 三、分阶段升级计划
### Phase 0：准备（30 分钟）
```bash
# 1. 建立升级分支
git checkout -b upgrade/wails-v3
# 2. CLI 更换（v2 的 wails CLI 不适用于 v3 项目）
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0
# 3. Go 依赖（v3 要求 Go ≥ 1.25.0，项目 Go 1.26+ 满足）
go get github.com/wailsapp/wails/v3@v3.1.0 && go mod tidy
# 4. 前端 runtime 包
pnpm --dir frontend add @wailsio/runtime
```
### Phase 1：Go 后端改造
**1.1 重写 `main.go`** —— 按[官方迁移示例](https://wails.io/migration/v2-to-v3)：

```go
//go:embed all:../../frontend/dist
var assets embed.FS
func main() {
hub := /* 保持原有 logx 初始化 */
svc := /* 保持原有 bindings.Service 初始化 */
app := application.New(application.Options{
Name: "Music Tools",
Services: []application.Service{
application.NewService(NewApp(svc, hub)), // main.App 整体注册为服务
},
Assets: application.AssetOptions{
Handler: application.AssetFileServerFS(assets),
},
})
app.Window.NewWithOptions(application.WebviewWindowOptions{
Title:  "Music Tools · 音乐工作台",
Width:  1280, Height: 800, // ← 从原 v2 options 搬运窗口参数
})
if err := app.Run(); err != nil {
panic(err)
}
}
```
**1.2 改造 `app.go`** —— 用服务生命周期钩子替换 `startup/shutdown`：
```go
type App struct {
    *bindings.Service // 嵌入保留：所有导出方法仍暴露给前端
    svc *bindings.Service
    hub *logx.Hub
    quitting atomic.Bool // 替代原 a.ctx.Err() 的关闭保护
}
// 显式指定服务名，前端调用路径保持 "main.App.<Method>"，与 v2 语义一致
func (a *App) ServiceName() string { return "App" }
func (a *App) ServiceStartup(ctx context.Context, _ application.ServiceOptions) error {
    app := application.Get()
    a.svc.SetEmitter(func(event string, payload any) {
        if !a.quitting.Load() {
            app.Event.Emit(event, payload) // 替代 runtime.EventsEmit(a.ctx, ...)
        }
    })
    a.svc.SetDirectoryDialog(func(title string) (string, error) {
        return app.Dialog.OpenFile().SetTitle(title).
            CanChooseDirectories(true).CanChooseFiles(false). // 目录选择 = OpenFile 变体
            PromptForSingleSelection()
    })
    a.svc.SetFileDialog(func(title string) (string, error) {
        return app.Dialog.OpenFile().SetTitle(title).PromptForSingleSelection()
    })
    a.svc.SetSaveDialog(func(title, defaultName string) (string, error) {
        return app.Dialog.SaveFile().SetTitle(title).
            SetFilename(defaultName).PromptForSingleSelection()
    })
    a.hub.Flush()
    app.Event.Emit("app:ready", map[string]any{ /* 内容不变 */ })
    return nil
}
func (a *App) ServiceShutdown() error {
    a.quitting.Store(true)
    a.svc.CancelTask()
    a.hub.Logger().Info("应用退出")
    a.hub.Flush()
    return nil
}
```
> 💡 官方说明：shutdown 回调应保持 <1s；`CancelTask` 是异步取消请求，符合要求。v3 的 `ServiceStartup` 返回 error 会中止启动，正好承接原 `startup` 的行为。
**1.3 删除绑定生成标签机制**：
- 删除 `bindingtag_bindings.go`、`bindingtag_default.go`
- 删除 `main.go` 中 `bindingGeneration` 相关分支，`config.yml` 落盘与 `logs/` 创建恢复为正常逻辑（v3 静态生成不执行程序，**不存在构建期产文件问题**）
- AGENTS.md 中"新增启动期落盘逻辑时同样要规避该模式"条款随之删除
### Phase 2：前端改造（改动最集中的部分）
**2.1 `api/bindings.ts`** —— 只改 `call()` 底座，40+ 方法定义零改动：
```ts
import { Call } from '@wailsio/runtime'
export async function call<T>(method: string, ...args: unknown[]): Promise<T> {
  try {
    return (await Call.ByName(`main.App.${method}`, ...args)) as T
  } catch (err) {
    const message = err instanceof Error ? err.message : String(err)
    // 非 Wails 环境（浏览器直开 vite）时保留原友好降级提示
    throw new Error(message)
  }
}
// bindings 对象其余内容完全不动
```
**2.2 `api/events.ts`** —— 只改 `on()` 的回调签名适配：
```ts
import { Events } from '@wailsio/runtime'
export function on<T>(event: string, handler: Handler<T>): () => void {
  // v3：回调收到 WailsEvent 对象，payload 在 event.data；On 本身返回取消函数
  const off = Events.On(event, (e: { data?: T }) => handler(e?.data as T))
  return () => { off() }
}
export function emit<T>(event: string, payload: T): void {
  void Events.Emit(event, payload) // v3 返回 Promise<boolean>（是否被 hook 取消）
}
```
> ⚠️ 这是**最容易出 bug 的点**：v2 是 `(...data) => data[0]`，v3 是 `(event) => event.data`。由于全部订阅都走此封装，改一处即可；但回归时必须验证 `log:batch`、`task:progress`、`task:item`、`task:done`、`task:queued`、`config:changed`、`app:ready` 全部事件。
**2.3 `env.d.ts`** —— 删除 `WailsRuntime`、`window.go`、`window.runtime` 三段声明（类型由 `@wailsio/runtime` 提供），保留 `vite/client` 与 `*.vue` 声明。
**2.4 `vite.config.ts`（可选增强）** —— 加官方 Vite 插件获得绑定/类型化事件 HMR：
```ts
import wails from '@wailsio/runtime/plugins/vite'
plugins: [vue(), wails("./bindings")]
```
### Phase 3：构建体系
**3.1 新增 `Taskfile.yml`** —— v3 以 Task 为构建核心（`wails3 build` 实际执行 Task），参照官方模板生成后固定输出路径为 `build/bin/go-music-tools.exe`，并加入 `generate:bindings` 任务（`wails3 generate bindings`）。
**3.2 `wails.json`** 改为 v3 结构：
```json
{
  "name": "go-music-tools",
  "frontend": {
    "dir": "./frontend",
    "install": "pnpm --dir frontend install --frozen-lockfile",
    "build": "pnpm --dir frontend run build",
    "dev": "pnpm --dir frontend run dev",
    "devServerUrl": "http://localhost:5173"
  }
}
```
**3.3 `build.ps1`** Step 4 修改：
```powershell

if ($wails3) { & wails3 build }  # 前置检查也从 wails → wails3
else { & go build -tags production,desktop -ldflags="-H windowsgui" -o $OutputPath . }  # ← v3 需加 tags
```
**3.4 `.gitignore`**：`frontend/wailsjs/` → `frontend/bindings/`（若采用生成模块方案；纯 `Call.ByName` 方案无生成物，但保留 ignore 以备渐进迁移）。
### Phase 4：文档同步（AGENTS.md 有强约束："结构/命令/边界变化必须在同一次改动中更新"）
- **技术栈行**：`Wails v2` → `Wails v3`
- **命令**：`wails dev` → `wails3 dev`；`wails build` → `wails3 build`；新增 `wails3 generate bindings`
- **架构边界**："`window.go.main.App.*`" → "`@wailsio/runtime Call.ByName('main.App.*')`"；"`window.runtime.EventsOn`" → "`@wailsio/runtime Events`"；删除 `-tags bindings` 相关两条；`frontend/wailsjs/` → `frontend/bindings/`
- **README**：CLI 安装命令改 `go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0`；徽章 Wails v2 → v3

## 四、架构边界保持（本次迁移的守护红线）
原约束"**后端业务包禁止 import Wails runtime**"在 v3 下依然成立且**不受破坏**：
- `ServiceStartup/ServiceShutdown/ServiceName` 全部放在 **main 包的 `App`** 上，`internal/bindings.Service` 继续保持纯净（仅接收注入的 emitter/对话框回调），`go test ./...` 仍可独立运行
- `application.ServiceOptions`、`application.App` 等 wails 类型只出现在 `app.go`/`main.go`，与 v2 时期 `runtime` 包只出现在 `app.go` 的格局一致

## 五、风险与缓解
| 风险 | 等级 | 缓解 |
|---|---|---|
| 事件回调签名差异（`data[0]`→`event.data`）遗漏某处直接调用 | 中 | 封装层强制收口 + Phase 5 事件全量回归；搜索 `EventsOn` 确认无旁路 |
| `Call.ByName("main.App.X")` 服务名解析不符 | 中 | 显式实现 `ServiceName() string`；首次迁移后跑一个绑定冒烟测试；必要时切换为 `-names` 生成模式核对命名 |
| `app:ready` 事件早于前端挂载而丢失 | 低 | 项目前端本就以 `GetAppInfo` 显式拉取（App.vue 中 `config.refresh()`），`app:ready` 仅辅助；必要时改为窗口创建后 emit |
| shutdown 阶段 emit 到已销毁窗口 | 低 | 用 `atomic.Bool` 替代原 `ctx.Err()` 检查（v3 `ServiceShutdown` 无 ctx） |
| vite 浏览器直开时 `@wailsio/runtime` 行为 | 低 | v3 下事件注册不抛错只是收不到；绑定调用 catch 后转友好错误，与现状语义一致 |
| Taskfile/build.ps1 产物路径漂移 | 低 | Taskfile 中显式固定 `build/bin/go-music-tools.exe` |
**回滚方案**：整个升级在独立分支；v2/v3 import path 不同可共存，出问题直接切回 main 分支即可，无中间态污染。

## 六、v3.1.0 特有的可选项（本计划默认不启用）
1. **实验性 CGO-free 构建**：`WAILS_PUREGO=1 wails3 build` 或 `CGO_ENABLED=0 go build -tags purego,production`——Windows WebView2 后端本就轻 CGO，可作为后续实验，不建议随本次升级引入
2. **Wake 构建系统**（`WAILS_EXP_USE_WAKE=1`）：官方明确是**单向迁移**且会拒绝不兼容的自定义命令，建议继续使用 Taskfile，待 Wake 稳定后再评估
